## 一、测试问题汇总

### 1.1 AVX2 实现 Stack Smashing 错误

| 参数集 | 错误阶段 | 退出码 | 详细信息 |
|--------|---------|--------|---------|
| Phoenix-SM3-128s-avx2 | 密钥生成 | 134 (SIGABRT) | `*** stack smashing detected ***: terminated` |
| Phoenix-SM3-192f-avx2 | 签名阶段 | 134 (SIGABRT) | `*** stack smashing detected ***: terminated` |
| Phoenix-SM3-192s-avx2 | 签名阶段 | 134 (SIGABRT) | `*** stack smashing detected ***: terminated` |

### 1.2 问题根因分析

**根本原因：SM3 x8 并行代码的输出长度不匹配**

- 标准 SM3 哈希函数输出固定为 32 字节
- 但 Phoenix 签名算法中，`SPX_N`（哈希输出长度）随参数集变化：
  - 128 系列：`SPX_N = 16`
  - 192 系列：`SPX_N = 24`
  - 256/384/512 系列：`SPX_N = 32/48/64`

- 当 `SPX_N < 32`（即 128 和 192 系列）时，x8 并行的 SM3 实现（`thash_sm3_simplex8` / `utilsx8`）会写入超过栈缓冲区分配的空间，导致栈溢出检测触发。

### 1.3 问题参数集特征

| 参数集 | SPX_N | 使用的并行实现 | 是否通过 |
|--------|-------|---------------|---------|
| Phoenix-SM3-128f-avx2 | 16 | x4 (thash_sm3_simplex4) | ✅ 通过 |
| Phoenix-SM3-128s-avx2 | 16 | x8 (thash_sm3_simplex8) | ❌ 失败 |
| Phoenix-SM3-192f-avx2 | 24 | x8 (thash_sm3_simplex8) | ❌ 失败 |
| Phoenix-SM3-192s-avx2 | 24 | x8 (thash_sm3_simplex8) | ❌ 失败 |

**关键发现：** 只有 Phoenix-SM3-128f-avx2 使用了 x4 并行实现，其他所有参数集都使用 x8 并行实现。x4 实现通过使用 `sm3_xof`（伪 XOF 变体）解决了输出长度问题，而 x8 实现仍使用标准 SM3，因此在 `SPX_N < 32` 时失败。

## 四、性能分析

### 4.1 AVX2 加速效果总结

| 操作 | 平均加速比 | 最高加速比 |
|------|-----------|-----------|
| 密钥生成 | **~2.0x** | 2.09x (256s) |
| 签名 | **~1.3-1.5x** | 1.57x (256f) |
| 验证 | **~5-9x** | 9.03x (256s) |

**验证阶段的加速比最高**，因为验证过程主要是哈希运算，更容易从 AVX2 并行化中受益。

### 4.2 参数集对比

- **f（fast）系列**：签名速度较快，但签名较大
- **s（small）系列**：签名较小，但签名速度慢得多
- 随着安全级别（n）的增加，所有操作的耗时显著增加

### 4.3 性能瓶颈

签名操作的主要开销来自 WOTS 公钥生成（占总签名时间的 78%-99%）：
- WOTS 公钥生成需要大量的 `thash` 调用
- `thash` 是整个签名算法中调用最频繁的哈希操作

### 4.4 Reference 实现的编译警告

384 和 512 系列的 Reference 实现存在编译警告：
```
warning: ‘__builtin_memcpy’ reading 48/64 bytes from a region of size 32 [-Wstringop-overflow=]
```

这表明 Reference 实现中也存在 `SPX_N > 32` 时的缓冲区溢出问题，但由于没有启用栈溢出检测（-fstack-protector），运行时未崩溃。

## 五、问题修复建议

### 5.1 短期修复

对于 `SPX_N < 32` 的参数集（128s、192f、192s），需要：

1. **引入 x4 并行实现**：参考 128f 的做法，添加 `utilsx4.c`、`thash_sm3_simplex4.c`、`hash_sm3x4.c`
2. **修改 Makefile**：将这些文件加入编译列表
3. **确保使用 sm3_xof**：使用伪 XOF 变体以支持变长输出

### 5.2 长期优化

实现真正的 SM3 XOF x8 并行 AVX2 版本，处理 8 路并行的位级填充和输出提取逻辑。
